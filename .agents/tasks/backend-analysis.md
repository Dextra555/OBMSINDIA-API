### `SalaryProcess` (implements `ISalaryProcess`) — `BusinessObjects/SalaryProcess.cs`

Core payroll computation engine. Uses raw ADO.NET + `SQLDataAccess`.

**Key methods:**

| Method | Description |
|---|---|
| `Process(branch, employeeType, remarks, period, lockProcess, currentUser, companyCode)` | Full salary processing run for a branch+period. Iterates all employees in Attendance, computes gross/deductions, inserts PaySlip rows. Handles PF, ESI, Professional Tax, TDS for Indian payroll. |
| `GetListWithBlankRow(branch, employeeType, dtDateJoinFrom, dtDateJoinTo, KDNVetting)` | Queries `vwKKDN` view; returns `List<KKDNExcelListDto>` for KDN/vetting report. |

**`Process()` SQL flow:**
1. `SELECT DISTINCT` from `Attendance JOIN Employee` for branch+period
2. `SELECT/INSERT/UPDATE SalaryProcess` (locking check)
3. `INSERT INTO SalaryProcessAudit`
4. For each employee: large JOIN query across `Employee`, `EmploymentDetails`, `EmployeeSalaryDetails`, `SalaryStructure`, `ClientMaster`
5. Reads CB (Commercial Breakdown) fields: `CB_Basic`, `CB_DA`, `CB_HRA`, `CB_HRAPercentage`, `CB_OtherAllowances`, `CB_NH`, `CB_NHPercentage`, `CB_AdvanceStatutoryBonus`, `CB_Leaves`
6. Calls `IProfessionalTaxService`, `IPFCalculationService`, `IESICalculationService` for Indian statutory deductions
7. Inserts to `PaySlip` table within transaction

## Services

### `PFCalculationService` (implements `IPFCalculationService`)

Indian PF calculation service.

**Methods:**
- `CalculatePF(basic, da, date)` — standard PF calculation
- `CalculatePFWithAge(basic, da, date, dob?)` — age-aware (employees >55 get zero PF)
- `IsPFApplicable(basic, da, date)` — returns true if total wages > 0
- `CalculatePFForPayslip(basic, da, otherAllowances, calendarDays, workedDays, date)` — matches Crystal Report formula: `pfWage = (basic+da+others)/calendarDays × workedDays`, capped at BasicSalaryLimit (₹15,000), rounded away from zero

**Data source:** `PFConfiguration` table (EF Core, `AsNoTracking`, ordered by `EffectiveDate DESC`)

---

### `ESICalculationService` (implements `IESICalculationService`)

Indian ESI calculation service.

**Methods:**
- `CalculateESI(gross, date)` — basic ESI
- `CalculateESIWithAttendance(gross, daysWorked, totalWorkingDays, date)` — proportional for partial months
- `IsESIApplicable(gross, date)` — gross must be ≤ BasicSalaryLimit (₹21,000)
- `CalculateESIForPayslip(earnedSalary, cbAdvanceStatutoryBonus, date)` — Crystal Report match: `esiWage = earnedSalary − cbAdvanceStatutoryBonus`, ESI = `Round(esiWage × EmployeeRate / 100, 0, AwayFromZero)` if esiWage < ₹21,000

**Data source:** `ESIConfiguration` table

---

### `ProfessionalTaxService` (implements `IProfessionalTaxService`)

Indian Professional Tax (PT) calculation service.

**Methods:**
- `CalculateProfessionalTax(gross, state, date)` — state-wise slab lookup
- `GetProfessionalTaxAmount(gross, state, date)` — returns tax amount only

**Period handling:** Semi-annual slabs: `taxAmount/6`; Annual slabs: `taxAmount/12`; Monthly: as-is.

**Data source:** `ProfessionalTaxConfiguration` table filtered by state + effective date

---

### `TDSCalculationService` (implements `ITDSCalculationService`)

Indian TDS (Tax Deducted at Source) calculation.

**Methods:**
- `CalculateTDS(annualIncome, ageGroup)` — slab-based tax + surcharge + 4% education cess
- `GetTDSDeduction(annualIncome, ageGroup)` — returns monthly TDS (`totalTax / 12`)

**Age groups:** 1 = below 60 (₹2.5L exemption), 2 = 60–80 (₹3L), 3 = above 80 (₹5L)

**Surcharge:** 10% above ₹1Cr, 25% above ₹2Cr, 15% above ₹5Cr

**Data source:** `TDSSlabConfiguration` table

---

### `GSTCalculationService` (implements `IGSTCalculationService`)

**Methods:**
- `CalculateGST(amount, hsnCode, supplierStateCode, recipientStateCode, invoiceDate)` — CGST+SGST for intra-state, IGST for inter-state
- `CalculateGSTByStateNames(...)` — accepts state names, converts to codes
- `GetApplicableGSTRates(invoiceDate)` — returns distinct GST rates

**Data source:** `GSTConfiguration` table by HSNCode

---

### `AttendancePeriodService` (implements `IAttendancePeriodService`)

Handles custom vs. calendar attendance periods.

**Methods:**
- `GetAttendancePeriodAsync(clientCode, year, month)` — async, looks up `ClientAttendancePeriod`
- `GetAttendancePeriod(clientCode, year, month)` — sync
- `GetCalendarMonthPeriod(year, month)` — standard calendar month

**Custom period logic:** StartDay from previous month, EndDay in reference month, PeriodKey = last day of reference month.

### `AttendanceExcelService` (implements `IAttendanceExcelService`)

Excel template generation and parsing for attendance upload using ClosedXML.

**Methods:**
- `GenerateAttendanceTemplate(period, branchCode)` — full detailed template (8 columns per day: WorkType, Client, TimeStart, TimeEnd, OTClient, OTStart, OTEnd, Remarks)
- `ParseAttendanceExcel(stream)` — parses detailed template

## Exception Handling & Logging

- **Global exception handling:** None. Most controllers use bare `throw;` in catch blocks, propagating exceptions as 500 errors with stack traces visible via `UseDeveloperExceptionPage`.
- **Logging:** Standard `ILogger<T>` injected in `FinanceController` and `ComplianceReportController`. Default log level in Development = `Information`; Production = `Warning`. No structured logging framework (no Serilog/NLog).
- **Console.WriteLine:** Used heavily in `EmployeeController.SaveAndUpdateEmployee()` for CB field debugging — not suitable for production.
- **SQLDataAccess exceptions:** FK violations (error 547) mapped to readable messages; all others re-thrown as `Exception` wrappers.
